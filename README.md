# PhiMC

> ## ⚠️ 非官方项目
>
> **PhiMC 是非官方同人项目，与鸽游（Pigeon Games）及《Phigros》官方
> 不存在任何授权、合作或运营关系。**
> 本项目不代表上述任何一方的立场，也未获其认可或背书。

在 Minecraft 里打音游谱面的 Fabric 模组：判定线、音符、Tap / Hold / Drag / Flick 判定、连击计分、特效谱渲染、在线谱面库、生存玩法，全部自己实现。

支持 **1.20 ~ 1.21.11 共 19 个 Minecraft 版本**。

> **本仓库不包含任何谱面、音乐或美术素材。**
> 谱面与音频由玩家自行放入 `config/phimc/songs/`，版权归各自作者所有。
> 安装器中内置的 4 张社区谱面**已征得谱师许可**，仅用于开箱即可试玩。

| 版本类型 | 完整版 `phimc` / 打歌版 `phimcplayer`，两个独立 jar，**二选一**（安装器里选） |

## 安装

### 方式一：安装器（推荐）

双击 `PhiMCSetup.exe`：

1. 自动定位 `.minecraft`（不对可以点「浏览」）
2. 选实例 —— 安装器会读取该实例的 MC 版本
3. 在「③ 安装选项」里选**版本类型**：`完整版（默认）` 或 `打歌版`
4. 点「安装」
5. 点「打开资源包文件夹」，把材质包 `.zip` 放进去（可选）

**两种版本二选一**，装哪种就写哪种 jar，安装器会顺手把另一种的 jar 删掉：

| | PhiMC（完整版） | PhiMC Player（打歌版） |
|---|---|---|
| jar / mod id | `phimc-<MC>.jar` / `phimc` | `phimcplayer-<MC>.jar` / `phimcplayer` |
| 打歌 | ✅ | ✅ |
| 物品 / 平板 / 芯片 | ✅ | ❌ |
| 生存玩法（商店/奖励/开箱） | ✅ | ❌ |
| 在线谱面库 | ✅ | ✅ |
| 给物品 / 发奖励 | ✅（仅单人；服务端没有「这一局打完了」的结果包） | **从不** |
| 在别人的服务器 | 服主装了同一个 jar → 物品/配方/战利品/开箱在服务端生效；没装 → 只能打歌 | ✅ 完整体验 |


> ### ⚠️ 二选一，不能同时装
>
> 两个 jar 打的是同一批 class（同一个源码树，只有 `fabric.mod.json` 不同），
> 打歌版的 `fabric.mod.json` 里写了 `"breaks": {"phimc": "*"}`，
> 同时放进 `mods/` 时 Fabric Loader 会**直接拒绝启动**并提示二选一。
> 安装器每次安装都会删掉另一种类型的 jar（不受「删除旧 jar」勾选影响），
> 并在日志里写明「写入了哪个 jar、删掉了哪个冲突 jar」。

> 安装器会在安装前清掉 `mods/` 里同 mod id 的旧 jar（按 jar 内 `fabric.mod.json` 的 id 判断，不只按文件名），所以升级不会出现两个版本打架。
> 不在 1.20 ~ 1.21.11 范围内的实例会被明确拒绝，不会装错。

### 方式二：手动

1. 装好 **Fabric Loader** + 对应版本的 **Fabric API**
2. 二选一放进 `mods/`（**只能放一个**）：
   - 完整版：`phimc-<你的MC版本>.jar`
   - 打歌版：`phimcplayer-<你的MC版本>.jar`
3. 启动游戏

首次启动会自动创建 `config/phimc/`（两种版本的曲目、材质包、设置目录完全一样）。

### 方式三：服主开服（同一个 jar 装服务端）

完整版 `phimc-<MC>.jar` 是**双端模组**（`fabric.mod.json` 里 `environment: "*"`，同时有
`main` 与 `client` 入口）：**同一个 jar** 放进客户端的 `mods/` 是完整版，放进专用服务端的
`mods/` 就把物品 / 配方 / 战利品 / 开箱赋谱 / 服务端存档带上服：

1. 服务端装 Fabric Loader + Fabric API，把 `phimc-<MC>.jar` 放进服务端 `mods/`
2. 首次启动会创建 `<服务端目录>/config/phimc/songs/` —— 把谱面包（`.zip` / `.pez`）放进去
   （也认 `<服务端目录>/songs/`），重启后日志会打印
   `[PhiMC] 找到 N 首谱面（服务端曲库：...）`
3. 玩法存档落在 `<服务端目录>/world/phimc/`（`profile.json` / `records.tsv`），按世界隔离；
   单人存档仍是 `saves/<世界名>/phimc/`

服务端真正生效的：物品注册、配方、原版箱子战利品注入、开箱赋谱、大肥鱼彩蛋、
芯片右键解锁写服务端存档。仍不可用的（原因）：图形界面与打歌（服务端无渲染）、
结算奖励（客户端还没把「这一局打完了」发给服务端，没有结果包）、商店扣款 / 平板赠品
（写的是客户端那份存档）、在线谱面库（客户端功能）。打歌版 `phimcplayer` 仍是**纯客户端**。

改造细节（入口拆分 / `javap` 常量池证据 / 服务端启动日志 / 剩余限制的完整清单）见
[`docs/REPORT-dedicated-server.md`](docs/REPORT-dedicated-server.md)。

## 打歌版：PhiMC Player（二选一）

同一份源码除了完整版 `phimc-<MC>.jar`，还产出一个**独立的「打歌 only」模组**（另一个 jar、另一个 mod id，
不是同一模组里的模式开关）。**19 个 MC 版本都有**，安装器里选「打歌版」即可：

| | 完整版 | 打歌版（PhiMC Player） |
|---|---|---|
| jar | `phimc-<MC>.jar` | `phimcplayer-<MC>.jar` |
| mod id | `phimc` | `phimcplayer` |
| 入口 | 谱面播放器物品 / 平板 | **`V`** 键 |
| 打歌 / 曲库 / 在线谱面库 | 有 | 有（同一套界面与判定） |
| 物品 / 配方 / 战利品 / 奖励 / 生存玩法 | 有 | **完全没有**（启动时一个物品都不注册） |
| 给物品 / 发奖励 | ✅（仅单人；服务端没有「这一局打完了」的结果包） | **从不** |
| 在别人的服务器 | 服主装了同一个 jar → 物品/配方/战利品/开箱在服务端生效；没装 → 只能打歌 | ✅ 完整体验 |
| 成绩 | 按存档 / 按服务器 | 按存档 / 按服务器 / 主菜单兜底存本地 |

> ### ⚠️ 两个 jar **只能二选一**
>
> 两个 jar 打的是**同一批 class**（同一个源码树，只有 `fabric.mod.json` 不同），
> 同时放进 `mods/` 会因类名重复互相打架。打歌版的 `fabric.mod.json` 里写了
> `"breaks": {"phimc": "*"}`，所以同时装时 Fabric Loader 会直接拒绝启动并提示二选一。
> 安装器会自动删掉另一种类型的 jar。

### 打歌版做什么

1. `V` 打开曲库（默认键位，可在「控制 → 按键绑定」里改，分类 `PhiMC`）
2. 选歌 → 开始 → 打歌
3. 结算：**只存成绩**，不发奖励、不写解锁、不碰背包
4. 成绩落点：
   - 单人：`saves/<世界名>/phimc/records.tsv` + `profile.json`
   - 多人：`config/phimc/servers/<服务器地址>/records.tsv` + `profile.json`
   - 主菜单里直接打歌：`config/phimc/servers/local/`
   - 地址里的 `:` `/` 等字符会换成 `_`（例：`play.example.com:25565` → `play.example.com_25565`）

曲库界面、材质包、打击音、在线谱面库、判定与计分与完整版**完全一致**（同一份代码）：
曲库副标题会写「纯客户端 · 成绩保存在本地」，「拷芯片」/ 商店 / 平板入口全部隐藏，
所有谱面一律可玩（**不读**解锁存档）。

### 打歌版不做什么

物品 / 创造页签 / 平板 / 商店 / 芯片 / 开箱掉落 / 大肥鱼融合 / 结算奖励 / 任何世界交互
—— 打歌版的入口 `PhiMCLiteClient` **不调用** `PhiMCRegistry.register()`，
所以这些注册在执行期根本不存在（不是「有代码但开关关掉」）。

## 怎么玩

### 1. 拿到入口物品

三种方式任选：

- **创造模式**：`PhiMC` 物品页签里的 **谱面播放器**
- **生存**：工作台合成 **平板**（见[生存玩法](#生存玩法)），右键打开
- **指令**：`/give @s phimc:chart_player`

### 2. 选曲

打开界面后选一首谱面，点「开始」。

- 曲库是空的？见[谱面放进哪里](#谱面放进哪里)
- 在线页签可以直接搜索下载

### 3. 打歌

音符沿判定线落下。**判定是全屏的**：不看点击位置，音符到线时有键按着就命中。

- **Tap / Hold**：到判定线时按着任意键（Hold 要一直按着）
- **Flick / Drag**：同一个性质，同样只需有按键输入，不分方向、不需要滑动

结算会给出分数、评级、连击、准确率。

## 谱面放进哪里

```
.minecraft/config/phimc/songs/
```

支持：

- **`.pez` 文件**（RPE / PEC / PGR 打包，自带音频与曲绘）
- **`.zip` 曲包**（内部含 `chart.json` + `info.txt` 或 `meta.json` + 音频）
- **文件夹**（解压后的谱面目录）

放进去后回到选曲界面按「刷新」。

> 音频通常就在谱面包里。如果谱面只有 `chart.json` 没有音频，请把音频和它放在同一目录。

## 设置

选曲界面 → 「设置」：

| 项 | 说明 |
|---|---|
| 判定偏移 | `-300ms ~ +300ms`，步进 10ms。`＋` = 谱面提前（音符更早到判定线） |
| 打击音量 | 默认较低（-15 dB），避免盖过音乐 |
| 打击音开关 | 关掉就只有音乐 |
| 材质包 | 选择 `config/phimc/respack/` 里的 `.zip`，旁边有「打开文件夹」 |
| 自动游玩 | 只演示、不写成绩、不发奖励 |

> 判定偏移是**全局**的（跟设备走），谱面解锁与成绩是**按存档**独立的。

## 在线谱面库

选曲界面 → 「在线」页签：

1. 输入关键词（曲名 / 谱师）后回车
2. 列表带曲绘、难度、评分、谱师
3. 点「下载」→ 自动落到 `songs/` → 列表自动刷新

右上角有 **「仅上架」** 开关：

- 开（默认）：只显示已上架、已过审的谱面
- 关：连未上架的也显示，行内灰字标注 `[未上架]`

> 在线谱面的版权归各自作者，本项目只做检索与下载。

## 生存玩法

### 平板

工作台合成：

```
紫水晶碎片   玻璃板   紫水晶碎片
红石粉       铁锭     红石粉
铜锭         铁锭     铜锭
```

右键平板 → 商店 / 曲库。平板有耐久（打歌消耗）。

### 商店

用物品购买谱面，价格按谱面随机（同一存档内固定，重开不变）。

### 芯片

```
铁锭  红石  铁锭
      铁锭
      金粒
```

→ **空芯片**

流程：

```
平板曲库里对「已解锁」的谱面点「拷芯片」
  → 空芯片变成「谱面芯片」（一芯一谱，不可改写）
  → 右键谱面芯片解锁该谱面（芯片不消耗，可重复用）
```

箱子战利品里也能开出**已经载好某张谱面**的芯片（打开箱子那一刻随机赋谱）。
普通箱子 25%、稀有结构箱 50%。

### 奖励

按评级发物资（含解锁谱面所需的物品）。自动游玩不发奖励。

### 赠送

新平板赠送 2 首可下载曲目。

## 常见问题

**谱面看不见 / 列表是空的**
检查是不是放进了 `config/phimc/songs/`，然后在选曲界面点「刷新」。

**打歌时谱面时间不动、音符不来**
多半是音频解码失败。看日志里 `[PhiMC] 音频播放失败`，把那个谱面文件发 issue。

**某些贴图线显示成纯色块**
部分谱面会故意放蒙版图（`mask_*.png`、`black.png`），那是谱面本身的效果。

**换存档后解锁没了**
解锁与成绩是**按存档**的，属于设计行为。全局只有设置项。

**联机时进度不保存**
以前是这样（多人拿不到本地存档路径 → 只读）。现在**按服务器落盘**：
`config/phimc/servers/<服务器地址>/`（地址里的 `:` `/` 换成 `_`），进出服务器时自动切换；
单人存档仍是 `saves/<世界名>/phimc/`。

**打歌版和完整版能一起装吗**
不能，二选一。两个 jar 的 class 名完全重复，同时装会被 Fabric Loader 直接拒绝（见[打歌版](#打歌版phimc-player二选一)）。

**没装正版能联机吗**
原版「对局域网开放」强制验证账号。需要装 `OfflineLAN` 之类的模组才能关掉在线模式。

## 从源码构建

### 环境

- JDK 25（Loom 1.19.2 要求）
- Gradle 9.8.2（Stonecutter 要求）
- `GRADLE_USER_HOME` 建议单独指定

### 构建

```bash
# 全部 19 个版本（逐版本串行，别一次并行，会 OOM）
cd mod
./build.ps1

# 单个版本
gradle :1.21.1:build
```

产物：

- `mod/dist/phimc-<MC>.jar` —— 完整版（19 个版本）
- `mod/dist/phimcplayer-<MC>.jar` —— 打歌版（19 个版本，构建变体；由
  `build.gradle` 末尾的 `liteJar` / `liteDist` 产出，`liteMcVersions` 控制哪些版本产出它）

> 打歌版的实现方式是**构建变体**：class 与完整版逐字节相同（直接从 `remapJar` 的产物里取），
> 只把 `fabric.mod.json` 换成 `mod/lite-resources/fabric.mod.json`（mod id `phimcplayer`，
> 入口 `PhiMCLiteClient`，`breaks: phimc`）。所以两个 jar 只能二选一。

### 目录

```
core/        纯 Java 引擎（解析 / 判定 / 音频），零 Minecraft 依赖
mod/         Fabric 侧（Stonecutter 多版本）
docs/        设计与验证报告
tools/       headless 探针与校验脚本
setup/       安装器源码（C#）
lib/         第三方 jar（gson / JLayer / JWebP）
```
